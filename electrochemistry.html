Usage Instructions

Adjust the sliders and selectors to set the simulation parameters. Use Tab/Shift-Tab to navigate inputs. The “Start” button begins the animation; “Reset” returns to rest. Keyboard users can adjust range inputs with arrow keys (accessible via labels). The canvas fallback text will appear if HTML5 canvas is unsupported.

Physics Model

This simulation treats each ball as a simple pendulum of length L and mass m. Between collisions, each satisfies the pendulum equation $$\ddot\theta = -\frac{g}{L}\sin\theta - c\,\dot\theta$$ (with damping coefficient c), which for small angles (<15°) approximates simple harmonic motion. The period is $T=2\pi\sqrt{L/g}$, independent of mass. When two balls collide, we apply 1D collision formulas conserving momentum and kinetic energy up to the restitution factor e. Specifically, for two balls of masses m₁,m₂ and incoming velocities u₁,u₂, the outgoing velocities are $$v_1 = \frac{m_1u_1 + m_2u_2 - m_2 e (u_1 - u_2)}{m_1+m_2},\quad v_2 = \frac{m_1u_1 + m_2u_2 + m_1 e (u_1 - u_2)}{m_1+m_2},$$ where 0≤e≤1 (1 is perfectly elastic, 0 fully inelastic). After collision, velocities are translated back to angular speeds. Energy lost to damping or inelasticity leads to gradually smaller swings. (We ignore air resistance and assume the strings constrain motion to a plane.)

Code and Animation

The code uses a single `` (via 2D context) to draw the balls and strings each frame. The animation loop is driven by `requestAnimationFrame`, yielding smooth motion and efficiency. The update step integrates each ball’s angle with simple Euler (sufficient for small timesteps) and checks for collisions as balls pass the bottom of their swing. Upon collision, we immediately apply the above velocity updates (pairwise collisions only) and reset angles to avoid overlap. Strings are drawn as lines and balls as shaded circles. This canvas-based approach offers high performance and easy pixel control, though we note that SVG or DOM-based methods (SVG circles/lines or HTML elements) could also be used. Canvas was chosen for performance with multiple moving objects and to allow fine-grained animation, at the expense of requiring custom accessibility handling.

Trade-offs: Canvas vs SVG vs DOM

FeatureCanvasSVGHTML DOM
Rendering Pixel-based drawing surface, extremely fast for many objects/animations Vector-based, retains object structure (scales crisp), easier event handling Not suited to complex shapes (used for layout); drawing via CSS is cumbersome
Interactivity All state must be managed in script; no native support for shapes or events Each element is in DOM (click/hover easily applied); better for accessible graphics Easy events on elements but limited to rectangular shapes; poor performance with many elements
Performance Generally highest FPS with many elements; redraw as bitmap, good for animation Better for few (≤1000) objects or static graphics; can slow with very many nodes Scales poorly beyond dozens of elements; layout cost high
Accessibility Canvas is a single element; must provide fallback/ARIA manually SVG content lives in DOM; can include ARIA roles and text for screen readers Native HTML is accessible; ARIA roles easily added

Testing Checklist

  • Verify physics: one ball out = one ball in; energy roughly conserved (with damping off).
  • Test parameter sliders (min/max values) and ensure live updates without page reload.
  • Test different browsers (Chrome, Firefox, Safari, Edge). Ensure canvas sizes scale correctly.
  • Keyboard accessibility: Tab through inputs, adjust via arrow keys, focus outlines visible.
  • Contrast check: blue theme provides sufficient text/background contrast.
  • Performance check: smooth animation at 60Hz with 7 balls. (Canvas re-draw is efficient.)
  • Fallback: Disable JS or use a non-supportive browser to see fallback text on ``.

Extensions & Presets

Possible enhancements include using **matter.js** or **planck.js** for more realistic physics, adding 3D CSS for a rotating cradle, or enabling mobile device tilt to simulate platform motion. Sample presets might include “Moon” (gravity=1.6), “Mars” (g≈3.7), or “Damped” (high damping) to demonstrate effects. One could also allow varying ball radii or asymmetric masses for experiments. Suggestions: adding audio on collision, supporting touch controls, or using SVG fallback for vector graphics.
